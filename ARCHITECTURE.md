# Architecture

What exists now, one row per module. The code is the detail; this page says where to look and which rules aren't obvious from the code. Reading rules: `docs/agents/architecture.md`. Terms: `CONTEXT.md`.

## How the pieces fit

```
extensions/base.json ─┐
variants/node/        ├─ image build ─► ghcr.io/valerid/dev-setup/node ◄── Template (templates/node/)
installer/  ──────────┘   (Base + Variant layers baked in)                  │
                                                                            ▼
                               Consuming Project: .devcontainer/ + extensions.json (Project layer,
                               installed by base/egress/start.sh at every container start)

skills/dev-container/ (host) ─► writes a project's .devcontainer/, reads this repo and the image
```

Dependency direction: the Template references the image, never the reverse. The skill imports the installer library; the installer and image never know about the skill. Tests depend on everything.

## Node devcontainer

| Module | Where | Owns | Rules that aren't obvious |
|---|---|---|---|
| Base material | `base/` | Files copied to root-owned system paths: Agent policy (`claude/`, `codex/`), yolo wrappers, host-credential scrubbing (`vscode/`, `git/`), egress start-up (`egress/`), missing-secret warning (`mcp/`) | `egress/start.sh` runs as root at start: it locks the Base allowlist, installs the Project layer, then re-locks with the full allowlist. On any failure it stops the container (fail closed). `wait-ready.sh` exists because `devcontainer up` doesn't wait for the entrypoint. |
| Extension installer | `installer/` (`src/index.mjs`, `src/cli.mjs`), schema `installer/extensions.schema.json`, layers `extensions/base.json`, `variants/node/extensions.json` | Validates Extension Manifests, fetches by exact SHA, merges layers, installs skills, Claude plugins and hooks, and MCP servers, and writes the egress allowlist and the secret-name list | Build mode installs the Base and Variant layers into the image. Start mode validates all layers but installs only the Project layer, with no state file: recreating the container is the uninstall. It writes secret names only, never values (ADR 0004). Codex plugins and hooks are unsupported. |
| Node Variant | `variants/node/` | `Dockerfile` (the only place that pins the base digest, pnpm, Claude Code and Codex) and the build-time `devcontainer.json` that becomes image metadata | Most hardening lives in image metadata (`devcontainer.metadata`), so it ships with the image and each project's Template copy stays small. pnpm policy: ADR 0001. |
| Node Template | `templates/node/` | Only what image metadata can't carry: `--cap-drop=ALL`, limits, read-only mounts, `remoteEnv` for the token and git identity, a starter `extensions.json` | CI rewrites the `image` option default to the published digest. |
| Acceptance suite | `tests/` (`lib.mjs`, `global-setup.mjs`, one file per area) | `npm test`: builds the image once per run, starts real containers and probes them as `node` | Teardown removes only what the run labelled or created; no prune, ever (`cleanup.test.mjs` proves it). The `@devcontainers/cli` pin lives in `tests/lib.mjs` and must match `ci.yml`, the skill and `quarterdeck/Dockerfile` (ci-efficiency 08, quarterdeck 02). |
| CI/release | `.github/workflows/ci.yml`, `scripts/check-pins.mjs`, `renovate.json` | The `changes` job picks which jobs run. The image is built and tested once, then that same image is published, signed and attested. The Template is published after it. | The job that runs tests never gets `id-token` or registry write access. After the Template publish, a guard fails the run unless `node:latest` is still the image. Every `uses:` needs a full SHA and every base image a digest. The acceptance job also builds the Quarterdeck image (never pushed); `check-pins.mjs` fails when its base digest, Claude Code or pnpm pin drifts from the Node Variant's. |

Egress details: ADR 0002. VS Code trade-offs: ADR 0003.

## Quarterdeck

| Module | Where | Owns | Rules that aren't obvious |
|---|---|---|---|
| Quarterdeck image | `quarterdeck/` (`Dockerfile`, `extensions.json`, `claude-policy.json`, `bin/qd-entry`, `bin/qd-server`, `bin/qd-first-mate`, `bin/qd-publish`, `fleet/config/`, `CHECKLIST.md`, `docker-proxy.conf`) | Base material plus the mates' tools (Docker CLI, `gh`, devcontainer CLI, Herdr, treehouse, FirstMate at a pinned commit in read-only `/opt/firstmate`). Built on Base, not a Variant (ADR 0006); never published | Claude policy is Base's minus `allowManagedHooksOnly`. `qd-entry` runs `base/egress/start.sh` as root against an empty `.devcontainer` (image allowlist only; fail closed), then `qd-server` as `node`, which parses the mounted token file by the names in `extensions.json` `secrets` (never sourced; root never reads it) and execs Herdr's server with them, so only Herdr's panes hold tokens. `qd-first-mate` (as `node`, backgrounded by `qd-entry`) then seeds the First Mate home `<work root>/fleet/firstmate` by copying `/opt/firstmate` (not cloning: git's ownership check refuses the root-owned source), adds only missing `fleet/config/*` files, writes Claude onboarding and trust for the home, and opens one Herdr workspace labelled `firstmate` running `claude --model opus --permission-mode auto`; no FirstMate file is edited (ADR 0008). `GIT_CONFIG_*` env disables project git hooks. `qd-publish <home> <project> <branch> <slug>` pushes the branch from the clone's git directory and opens the pull request with hooks forced off (mechanism in the script's header). |
| Mate procedures | `quarterdeck/skills/qd-first-mate/`, `quarterdeck/skills/qd-spec-run/` (Brief/report references), `quarterdeck/fleet/charter.md` | Managed skills installed under `/etc/claude-code/.claude/skills`; Charter template at `/opt/qd/fleet/charter.md`. First Mate provisions and hands off; Second Mate directs planning, ordered one-commit tickets, one retry, publish and the correlated report | Skills use FirstMate commands, never Docker or the launcher directly; only the Second Mate starts project Crewmates. Private Brief edits preserve generated safety and delivery-contract lines (ADR 0008). Structural and token-free loop coverage is in `tests/quarterdeck.test.mjs`, using the Node-derived `tests/fixtures/quarterdeck-crewmate/` with real FirstMate/Herdr commands. The fixture fetches full public FirstMate history to satisfy its lineage guard and simulates Stop hooks; stock shallow-home dispatch, real-agent supervision and publish-route proof remain outstanding. |
| Claude launcher | `quarterdeck/bin/claude` | FirstMate's unchanged argv routes from the worktree pool into the owning home's running project container; elsewhere execs the real Claude | Resolves the home from `FM_TASK_INBOX` and creator/home labels, refusing missing or ambiguous containers. Seeds/merges container-local Claude trust as `node`, forwards only allowed environment names, and sets the Docker process's Herdr hint. JSONL launch logs exclude prompts. Publish routing is not implemented. See `quarterdeck/PROJECT-CONTAINERS.md`. |
| Project-container creator | `quarterdeck/bin/qd-project-up` | Fetches `origin/main`, exports its `.devcontainer/`, renders the decision-34 mounts, and starts the pinned image through the devcontainer CLI and proxy | Reuses by home/project/tree labels; only its labelled containers are replaced. Template-only `runArgs`; GitHub/secret-named environment entries and project lifecycle commands are dropped. The creation CLI gets a temporary home and minimal environment, with only the optional read-only Agent Extensions token mapped to `DEV_SETUP_GITHUB_PAT` by name (ADR 0010); other credentials are excluded. The CLI currently persists that allowed token in `/etc/environment` (ticket 08 blocker, security-review 05). Retained Features remain trusted executable input, not proven isolation; see `quarterdeck/PROJECT-CONTAINERS.md`. Worktree Git redirection is accepted for the MVP (ADR 0009). |
| Host command | `quarterdeck/bin/quarterdeck` | `quarterdeck [attach\|stop\|rebuild]`, mounts the user's token file (`QUARTERDECK_SECRETS`) read-only after checking owner and mode, tested by `tests/quarterdeck.test.mjs`; ready means egress locked, Docker answering, Herdr running and the `firstmate` workspace present; passes `QD_WORK_ROOT` and the host's four Git author/committer identity variables by name | The ownership label goes on the container, never the image (containers inherit image labels). Default bridge, no user network: Base's `flush ruleset` removes the embedded DNS rules. Docker goes through a digest-pinned socket proxy (`quarterdeck/docker-proxy.conf` holds the pin and the allowed list) on a Unix socket in a volume, so Base's egress is unchanged; the proxy and volume have their own label key and `stop` removes them. Accepted gap: the proxy cannot see a container-create body. Put it on the path with `ln -s`, see README. Work-root folders it creates are owned by the host user, so `node` (uid 1000) can write them only on a uid 1000 host. |

## dev-container host skill

| Module | Where | Owns | Rules that aren't obvious |
|---|---|---|---|
| Skill prompt | `skills/dev-container/SKILL.md`, `references/<operation>.md` | The conversation: routing, confirmations, guardrails | No commits. Secret values are never asked for, read or written. A digest is written only after `verify-image` passes. `docs/agents/` and `.scratch/` are left alone. |
| Skill helper | `skills/dev-container/scripts/` (`dev-container.mjs`, `commands.mjs`, `manifests.mjs`, `image-layers.mjs`, `inspect.mjs`, `status.mjs`) | All exact steps, as a JSON CLI (`--help` lists them): detecting the Variant, rendering the Template, validating, verifying the image, planning a removal, inspecting an extension, reporting status | Plans and `inspect` are read-only. Only `render-template` and the lockfile commands write project files. The image layers are read from the image with `docker create` and `docker cp`, never by starting or pulling it. `verify-image` accepts only `ci.yml` on `main` and fails closed. |
| Variant metadata | `variants/<name>/variant.json` | Description and the files that identify a project's toolchain | |
| Presets | `presets/<name>.json` | Named sets of Agent Extensions, copied into a project with a `preset` tag | Copied, not referenced (ADR 0005). None exist yet; format in `presets/README.md`. |
