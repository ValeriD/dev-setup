## Node devcontainer (walking skeleton)

Proposed design: `.scratch/node-devcontainer/design.md`. Implemented: image, Template, egress start-up step, credential isolation, pnpm policy, extension installer (build and start mode: skills, Claude plugins and hooks, MCP servers with secrets), Consuming Project layer at container start, acceptance suite, CI, Renovate config and weekly rebuild.

Secret names (never values) go to `/etc/dev-setup/mcp-secrets`; MCP server names must be unique across layers. Tests: `installer/test/` against local bare-git fixtures (`npm run test:installer`). Claude plugins and hooks (`src/claude.mjs`, same `installBuild`/`installStart`): per layer (`image`, `project`) a root-owned `directory` marketplace `dev-setup-<layer>` under `/opt/dev-setup/marketplaces/<layer>` (plugin trees copied from SHA-pinned commits, `pins.json` records each source; a marketplace-referenced plugin is re-pinned and its external source must carry a SHA) and hook scripts under `/opt/dev-setup/hooks/<layer>`. No plugin seed and no `claude` run: Claude reads the directories in place. Egress: the start-up step consumes an allowlist file (override with env `EGRESS_ALLOWLIST`) and knows nothing of manifests; the installer emits that file. Test seam: `tests/` probes as `node` and asserts the container stopped on a broken allowlist.

Dependency direction: Template references the image; the image never references the Template; tests depend on everything.

## dev-container host skill

Proposed design: `.scratch/dev-container-skill/design.md`. Implemented so far: onboarding (verified image digest), Presets (adopt, remove, save, edit), migrate, verified image updates, egress domains and secrets, add/remove single Agent Extensions after review, status and Preset resync.

| Module | Anchor | Owns |
| --- | --- | --- |
| Skill prompt | `skills/dev-container/SKILL.md`, `references/<operation>.md` (onboard, migrate, update, presets, egress-and-secrets, extensions, status: rendering and Preset resync) | Conversation: routing, confirmation points, guardrails (only `verify-image` digests are written, no commits, secret values never asked for, read or written, `docs/agents/` and `.scratch/` left alone, `/setup-matt-pocock-skills` only reminded). Installed by symlinking the folder into `~/.claude/skills`. |
| Skill helper | `skills/dev-container/scripts/` | Node ESM CLI, JSON on stdout. `dev-container.mjs` checks the checkout found through its real path (and the `~/.claude/skills/dev-container` link) before anything else, exit 3 = re-link. `commands.mjs`: `variants`, `resolve-target`, `image-digest` (`docker buildx imagetools`, unverified, not used by the flows), `verify-image` (cosign signature + provenance in a pinned container, identity `ci.yml` on `main`; fails closed; then image labels and, with `--current`, the change summary), `render-template` (fills `${templateOption:…}` from the local `templates/<variant>/`, adds an empty Extension Manifest; `--replace` deletes an existing `.devcontainer/` first, for migrate), `validate` (`jsonc-parser` + installer `validateManifest` and `mergeLayers`; counts `preset` tags; checks each named secret has a `remoteEnv` `${localEnv:…}` reference), `presets` (lists and checks `presets/*.json`), `plan-remove-preset` (read-only: every tagged entry, and the Preset's top-level egress that no remaining entry or adopted Preset needs, as a proposal since top-level egress is untagged), `vscode-settings`, `up`, `first-lockfile`, `import-lockfile`, `frozen-install` (all four through the devcontainer CLI via `npx`, same pin as `tests/lib.mjs`; pnpm runs only in the container). Only `render-template` (into `.devcontainer/`) and the lockfile commands (`pnpm-lock.yaml`, `package.json`, the converted lockfile, through the container) write project files. `manifests.mjs`: shared read-only manifest and Preset reading (`readProjectManifest`, `listPresets`, `egressNeededBy`, `readJsonc`). `inspect.mjs`: `inspect` (resolve a Pinned Ref, fetch with the installer's `fetchBySha`, inventory the content read-only, propose or refuse the entry through installer validation; git, `npm:` and `https://` MCP sources) and `plan-remove` (read-only removal plan with egress nothing staying needs). Neither runs anything from, or inside, a fetched tree. `status.mjs`: `status` (read-only; builds on `validate` and `verify-image`, which `commands.mjs` hands it; Preset drift with exact `resync` entries, Pinned Ref ages, project egress, unset host variables by name only (the PAT host variable behind remoteEnv's `DEV_SETUP_GITHUB_PAT` line as a note, `env.pat`, not in `missing`), and a pending recreate for the container found by its `devcontainer.local_folder` label, from the applied-manifest hash, image and `remoteEnv`). Test seam `DEV_SETUP_GIT_BASE`. No subcommand accepts a secret value. Own `package.json`/lockfile (`jsonc-parser` exact). Tests: `scripts/test/` (`npm run test:skill`), `tests/dev-container-skill.test.mjs` (also `status` against a real container), manual `docs/manual/dev-container-skill-checklist.md`. |
| Variant metadata | `variants/<name>/variant.json` | Description and detection files, read by `variants`. |
| Presets | `presets/<name>.json` | Extension Manifests with a required `description`, entries untagged. Copied into projects with a `preset` tag on each entry (ADR 0005; both fields are optional in the installer schema and ignored by the installer). Read by `presets`, written by the agent. No example Preset yet; format in `presets/README.md`. |

Dependency direction: prompt → helper → installer library (relative import) and repository data. The installer and images never reference the skill.
