# Architecture

Current-state index. Details for each area live in `docs/architecture/<area>.md` when needed. See `docs/agents/architecture.md` for the reading rules.

## Node devcontainer (walking skeleton)

Proposed design: `.scratch/node-devcontainer/design.md`. Implemented so far: image, Template, egress start-up step, credential isolation, pnpm policy, extension installer (build and start mode, skills only), Consuming Project layer at container start, acceptance suite, CI. Not yet: plugins/hooks/MCP, Renovate.

| Module | Anchor | Owns |
| --- | --- | --- |
| Base material | `base/` | Files copied to fixed root-owned system paths: `bin/claude-yolo`, `bin/codex-yolo`, `claude/managed-settings.json` (to `/etc/claude-code`), `codex/config.toml` (to `/etc/codex`, lowest layer so yolo flags still win). Host-credential isolation: `vscode/dev-setup-scrub.sh` (to `/etc/profile.d`, hooked into `/etc/bash.bashrc`, run by `postStartCommand`), `git/gitconfig` (to `/etc/dev-setup`, read-only target of `GIT_CONFIG_GLOBAL`), `bin/git-credential-dev-setup` (PAT from `DEV_SETUP_GITHUB_PAT`, github.com only). `egress/` (to `/usr/local/share/egress`): `allowlist.txt` is generated at image build by the installer from the manifests (one domain per line), `start.sh` (root start-up step: locks the Base allowlist, runs `installer install --mode start` on `${DEV_SETUP_WORKSPACE}/.devcontainer/extensions.json` if present, re-locks with the full allowlist; fails closed by `kill -TERM 1` after writing `/run/egress/failed`, writes `/run/egress/ready` on success), `wait-ready.sh` (the image `postStartCommand` runs it as `node`: `devcontainer up` does not wait for the entrypoint, so this is what makes `up` fail with the reason), `render.sh` (dnsmasq conf + nftables ruleset), `selftest.sh`. Later hardening lands here. |
| Extension installer | `installer/`, `extensions/base.json`, `variants/node/extensions.json` | Node ESM, no build step; its only dependency is `ajv` (exact version, frozen `pnpm-lock.yaml`; transitive `fast-uri` is held at an older version by `pnpm-workspace.yaml` overrides so every package passes the 7-day release age). Library entry `src/index.mjs` (schema validation, Pinned Ref check, kind x Agent table, fetch-by-SHA, layer merge, allowlist assembly) with a thin `src/cli.mjs` (`install --mode build --manifest FILE...`). Published schema `extensions.schema.json` (manifests reference it via `$schema`). Build mode copies skills (verbatim, no symlinks, never executed) fetched by exact SHA into `/etc/claude-code/.claude/skills` and `/etc/codex/skills`, and writes `/usr/local/share/egress/allowlist.txt`; the Base Egress Allowlist lives in `extensions/base.json`. Start mode (`install --mode start --manifest ... --project FILE`) validates all layers together but installs only the project layer's skills, to the same root-owned system paths (container filesystem, no state file: recreating the container is the uninstall; a restart overwrites in place) and writes the full allowlist to `--egress-out`. Codex `plugin` and `hook` are unsupported kinds (D3); other kinds validate but are not installable yet. Tests: `installer/test/` against local bare-git fixtures (`npm run test:installer`). |
| Node Variant | `variants/node/` | `Dockerfile` (the one place for the base digest and pinned pnpm/Claude Code/Codex versions); `.devcontainer/features/egress/` is a local Feature carrying only the root `entrypoint` (the devcontainer CLI requires local Features under `.devcontainer/`); `devcontainer.json` is build-time only and becomes the image's `devcontainer.metadata` (`containerUser` root for the entrypoint, `remoteUser` node, `capAdd` NET_ADMIN/NET_RAW/DAC_READ_SEARCH (the last so root can read the manifest in an owner-only project directory), env `DEV_SETUP_WORKSPACE`, `no-new-privileges`, init, env including the pnpm/npm supply-chain policy as `pnpm_config_*`/`NPM_CONFIG_*`, login volumes). Build context is the repo root, filtered by `.dockerignore`. |
| Node Template | `templates/node/` | Only what image metadata cannot carry (plus a starter `.devcontainer/extensions.json` with `$schema` and an empty list): `--cap-drop=ALL`, limits, `initializeCommand`, read-only mounts of `.git/hooks`, `.git/config`, `.devcontainer`, `.vscode`. `remoteEnv` passes the PAT (host var named by option `patEnvVar`) and git identity (`GIT_AUTHOR_NAME`/`GIT_AUTHOR_EMAIL`) from the host. Option `image` selects the image. |
| Acceptance suite | `tests/` | `npm test`: builds the image, publishes the Template to a throwaway local registry, applies and starts it with the devcontainer CLI, probes as `node`. `credentials.test.mjs` covers host-credential isolation with fake tokens; manual VS Code checklist in `docs/manual/vscode-reopen-in-container.md`. `extensions.test.mjs` derives throwaway images from the built one and runs the installer there against a fixture repo (skill visible to Claude via its init event and to Codex via its model request). `project-layer.test.mjs` covers the project layer (skill and egress domain appear on recreate, are root-owned and read-only, vanish on removal; an invalid manifest fails `up` naming the entry) with a local bare-git fixture mounted at `/fixtures` and `DEV_SETUP_GIT_BASE` (test seam read by `start.sh`). `pnpm-policy.test.mjs` runs pnpm in fixture projects against `fixtures/registry-stub.mjs`, a dependency-free registry stub on container loopback with controlled publish times. |
| CI/release | `.github/workflows/ci.yml`, `scripts/check-pins.mjs` | PR pin check and acceptance run; on `main`: build and push, cosign keyless sign, SBOM and provenance attestations (pushed to the registry), Template publish with the `image` option default rewritten to the digest. |

Egress: the start-up step consumes an allowlist file (override with env `EGRESS_ALLOWLIST`) and knows nothing of manifests; the installer emits that file. Test seam: `tests/` probes as `node` and asserts the container stopped on a broken allowlist.

Dependency direction: Template references the image; the image never references the Template; tests depend on everything.
