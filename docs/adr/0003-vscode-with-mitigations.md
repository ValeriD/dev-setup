# Keep VS Code attach despite credential forwarding

VS Code "Reopen in Container" forwards the host ssh-agent, which can't be turned off (microsoft/vscode-remote-release#11413), and shares the git credential helper and IPC sockets that allow running commands on the host, so it is not a security boundary. We accept it for UX and mitigate inside the container: `SSH_AUTH_SOCK` is cleared, the forwarded git credential helper is removed, sensitive repo paths are mounted read-only, and pushes go through a single-repo fine-grained PAT. The remaining risk is that code running while VS Code is attached can reach the host. We treat it as acceptable because the Egress Allowlist, blocked install scripts and the release-age cooldown make a malicious package landing unlikely. Moving to a microVM (e.g. Docker Sandboxes) is the planned later hardening step.
