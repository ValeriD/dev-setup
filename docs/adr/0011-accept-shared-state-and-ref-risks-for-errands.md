# Accept shared-state and ref risks for Errands on a Project with no remote

A Project with no remote lives in the First Mate's own home, and its Crewmates run in a Project container that mounts that home's `state/` and the Project's git store. Three risks follow. The user accepts them; each has a limit, and none is a claim of isolation.

- **Signal files are shared across the First Mate's Projects.** Every local Project's container mounts the home's `state/`, so a Crewmate in one Project could forge a "done" for another. This widens the limit already accepted for the MVP, where a Crewmate could forge its own Project's signal. A landing still needs the user's word, and `fm-merge-local.sh` fast-forwards only to the head FirstMate recorded and refuses a dirty working tree, a moved `main` or a head that differs from the record.
- **A Crewmate can move any ref in its own Project's git store, `main` included.** The recorded config tree (`<work root>/quarterdeck/local-projects/<name>`, mounted by no Project container) keeps this from changing what the container is built from. It does not stop unaccepted commits from appearing on `main`. The user's checked-out files do not change, and `git status` in the main folder shows the difference.
- **`fm-merge-local.sh` is fast-forward only and latches the first observed `done` head.** If the user commits on `main` while an Errand runs, or the branch changes after `done`, the accept is refused. Nothing is forced. Revised work becomes a follow-up Errand with a new task id (the design's decision of 2026-11-19), because the FirstMate fork is not edited (ADR 0008). The old task and its branch stay until the follow-up lands.

Two further limits come from the same design and are recorded in [project containers](../../quarterdeck/PROJECT-CONTAINERS.md): the config record and the local Variant record are only as trusted as the work root, which mates can write; and `qd-project-rm`'s refusal for open work reads `state/`, which a Project container can write, so the user's confirmation in the `qd-project` skill is the other guard.

The Git gate and the hardening pair that ADR 0009 waits for would also narrow these. See [ADR 0009](0009-accept-worktree-git-redirection-for-the-mvp.md).
