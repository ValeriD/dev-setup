# Quarterdeck manual checklist

Rows the token-free tests cannot prove because they need a real Claude session, real tokens, or GitHub. Run a row per slice, with your own token file (see `quarterdeck/bin/quarterdeck`). A row is ticked only when its pass condition holds on the first try, with no manual keystroke.

Every row has the same columns: scenario, setup, what to look at, what a pass is.

Ticket 08's real-token row is **blocked** until the `/etc/environment` persistence in security-review concern 05 is resolved or explicitly accepted by the human. The instructions below are for that later human validation, not authorization to run them now.

For ticket 08, provision a fine-grained token with **Contents: read-only**, restricted to `ValeriD/skills`, using the user-owned token file consumed by ticket 03. Start a fresh Herdr session after changing that file, then deliberately recreate only the verified project container (see `PROJECT-CONTAINERS.md`). Never paste token values, raw `env`, `git credential fill` output or `docker inspect` into evidence. Run these checks yourself with tracing disabled; record only exit statuses and permission denials. Use HTTPS URLs without embedded credentials, `GIT_TERMINAL_PROMPT=0`, and no fallback credentials. A dry-run push to a unique nonexistent disposable branch must fail with a GitHub write-permission denial: a network error or a successful no-op is not evidence. Do not attempt a real push with a potentially mis-scoped token.
